# WorkBuddy → ZCode / Xiaomi MiMo Desktop

固定本机地址：`http://127.0.0.1:18181/v1`，OpenAI Chat Completions 协议。只监听回环地址，需要 `runtime/client.json` 中的随机本机密钥；这不是 WorkBuddy 上游令牌。

复用已安装在 DSH Desktop `web` profile 中的 `dsh-connect-workbuddy` 公共导出，不修改两个客户端的程序文件。账号来源为当前 Windows 用户的 Helper 加密账号库，模型目录来自真实 WorkBuddy 上游。不会改变 DSH 设置中保存的账号选择。

## Helper 全账号池

ZCode 与 MiMo 共用同一个账号池，按请求轮换 Helper 中已启用、授权有效且有余额的国内账号。按真实账号 UID 去重，不导入 DSH 历史重复项。5 个账号均保留在状态列表中，授权失效或停用的成员不会被用于请求。

每 30 秒持续读取 Helper 账号库，新增、删除、停用及重新登录自动反映到转接服务；余额每 5 分钟检查。界面余额仍有缓存，实际消费由 WorkBuddy 对各账号单独结算。每次请求选择一个账号，不把五个余额合并成一个余额。

同一个 30 秒同步周期也会更新 ZCode、MiMo 的独立账号菜单配置。只在账号增删时写入，修改前备份，保留已有账号的自定义名称、模型设置和其他供应商。打开中的模型菜单可能需要关闭后重新展开。账号面板会分别显示三处的同步状态；失败会在下个周期重试，不会显示为已完成。

DSH 使用运行中 Desktop 插件的导入接口合并新增有效账号，后续 Helper 凭据更新也会同步。DSH 未打开时稍后重试。DSH 中的历史重复项与当前选择保留；Helper 中移除账号只会让转接及两个客户端的托管入口移除，不会删除 DSH 中已保存的历史凭据。

账号令牌只经 Windows DPAPI 解密后在进程内使用，不另存明文令牌。需要续期时调用 Helper 自己的受本地会话保护的积分刷新接口，由 Helper 保存加密刷新结果。读取账号库失败时暂停后续账号选择，避免继续使用可能已被删除或停用的成员。

保留插件的流开始前故障切换；同一请求不会反复尝试同一个账号。模型整体繁忙及错误请求不会触发跨账号重试，已开始输出的流不会因失败而重放。

携带本机 API key 的 `GET /v1/accounts` 返回安全状态摘要，包含账号名称、状态、缓存余额及选择次数，不包含 WorkBuddy 令牌。`Check-Accounts.ps1` 可直接显示这份摘要。`uses` 是账号被选择的次数，不是成功请求数或扣费金额。

`Start-Bridge.ps1` 在后台启动；`Stop-Bridge.ps1` 只结束入口路径和 PID 都匹配的本服务。Node.js 以及当前 DSH 插件需保留。模型查询、SSE 流式工具调用由上游插件处理；本服务为非流式请求补充标准 JSON 响应转换。

`Configure-ZCode.ps1` 按已有 schema 合并供应商；修改前把原配置备份在 ZCode 自己的 `v2/local-backups`，保留其他供应商。客户端内仍需确认模型显示及真实请求结果。

`runtime/` 含本机密钥与运行数据，禁止上传 GitHub或分享。此目录内的代码未随先前两个公开仓库自动发布。

测试：`node --test server.test.mjs helper-pool.test.mjs`。服务健康、模型列表、真实完成和客户端界面分别验证，不能相互代替。`verify-pool.mjs` 会对当前可用账号逐一发送真实 Hy3 最小请求，消耗少量积分，仅需验证时手动执行。

## 已完成的桌面验证（2026-10-26）

- ZCode 与 Xiaomi MiMo 均已在原生模型菜单显示 `WorkBuddy 本机账号` 和 19 个模型。
- 两个客户端分别新建独立对话，选择 Hy3，发送“接入验证：请只回复 OK，不调用工具，不读取或修改任何文件。”，均实际收到 `OK`。
- 桌面 `WorkBuddy 接入 ZCode-MiMo` 启动后台转接，`停止 WorkBuddy 转接` 关闭本转接。使用客户端前需保持转接运行。
- 仅 Hy3 完成了客户端实际对话验证；其余模型已导入，未逐一调用验证。

全账号池升级后，多个 Helper 账号全部纳入；部分账号在实时授权检查及 Helper 刷新后需要重新登录。这是验证时的状态，以 `Check-Accounts.ps1` 为准。
